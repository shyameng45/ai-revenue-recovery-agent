Yes — this can be made into a proper DBMS project, not just a task list.

The core idea for GrooupSync should be:

Don't measure “how much work is completed.” Measure whether work is acknowledged, ownership is clear, people are responsive, and the project structure is becoming unsafe.

But importantly, Wi-Fi outage should NOT immediately become a critical alert.

Smart alert engine

I'd use an evidence-based severity model:

Signal	Result
1 missed heartbeat	Ignore / informational
Temporary network failure	Warning
Multiple consecutive failures	Investigate
Other members active but one member remains silent	Higher risk
Assignment unacknowledged past threshold	Warning
Non-member assigned a task	Structural alert
Owner silent + unresolved alerts	Escalation
Multiple independent signals	Critical

So the system doesn't say:

❌ "Rohan is offline → CRITICAL"

Instead:

⚠️ "Rohan has not acknowledged 2 assignments and has shown no activity for 4 hours."

That's much more defensible for a DBMS project.

orphan foreign keys

API fields that don't match DB fields

That gives you a real DBMS concept, rather than making GrooupSync just another CRUD application.
