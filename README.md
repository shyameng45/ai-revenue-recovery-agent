# AI Revenue Recovery Agent

An AI agent that detects failed subscription payments, diagnoses why they
failed, and takes recovery action — smart retries for recoverable failures,
and warm Hinglish reminder messages for customers whose payment method needs
attention.

Built for the **Razorpay AI Buildathon 2026** — AI Revenue Recovery track.

## Problem

Recurring/subscription payments fail silently — expired cards, insufficient
funds, bank declines. This leaks revenue because failed payments aren't
tracked or acted on at scale, and customers often don't even realize their
payment failed until their service is cut off.

## Solution

An automated agent that:
1. **Detects** failed payments and classifies each as a "soft fail" (worth
   retrying, e.g. insufficient funds) or "hard fail" (needs the customer to
   act, e.g. expired card).
2. **Diagnoses** the failure using an LLM and decides the right recovery
   action.
3. **Recovers** revenue via smart retries and a friendly, natural Hinglish
   reminder message — not a robotic collections notice.
4. **Logs everything** to a full audit trail, with a metrics dashboard
   showing money recovered vs. still at risk.

## Tech Stack

- **Backend**: Python + FastAPI
- **Database**: SQLite (via SQLAlchemy ORM)
- **AI**: OpenAI API (gpt-4o-mini) for diagnosis + Hinglish message generation

## Project Structure

## Setup

1. Create a virtual environment and install dependencies:
   ```bash
   python3 -m venv venv
   source venv/bin/activate       # Windows: venv\Scripts\activate
   pip install -r requirements.txt
   ```

2. Add your OpenAI API key to `.env`:
   ```
   OPENAI_API_KEY=your_key_here
   ```
   **Note**: `.env` is gitignored — never commit your key.

3. Seed synthetic data:
   ```bash
   python -m app.data.seed
   ```

4. Run the server:
   ```bash
   uvicorn app.main:app --reload
   ```

5. Open [http://localhost:8000/docs](http://localhost:8000/docs) for interactive API docs.

## API Endpoints

| Method | Endpoint             | Description                                      |
|--------|-----------------------|---------------------------------------------------|
| GET    | `/api/queue`          | View all failed payments awaiting recovery        |
| POST   | `/api/recover`        | Run one full recovery cycle (detect → AI → act)   |
| GET    | `/api/metrics`        | Dashboard: recovered amount, still at risk, rate  |
| GET    | `/api/audit-trail`    | Full log of every recovery action taken           |
| GET    | `/api/payments`       | All payments with current status (debug/demo)     |

## Demo Flow

1. `GET /api/queue` — see the failed payments the agent found.
2. `POST /api/recover` — trigger the agent; it diagnoses each one and
   generates a Hinglish recovery message.
3. `GET /api/metrics` — see the recovery rate and amount recovered.
4. `GET /api/audit-trail` — see every action logged, with the exact
   message sent to each customer.

## Notes

- Data is synthetic (generated by `seed.py`) for demo purposes — no real
  payment data is used.
- Stopping rule: soft-fail payments get up to 3 automatic retries before
  being marked "abandoned" and escalated, rather than retrying forever.
